# Modèle éditorial du contenu pédagogique

Ce document définit le rôle de chaque type de page afin d'éviter que le cours, l'exercice guidé, le Projet Web et l'aide-mémoire répètent les mêmes explications.

## Principe général

Une notion possède une **page canonique** où elle est expliquée. Les autres pages la réinvestissent sans la réenseigner au complet.

```text
Cours
  explique et montre
        ↓
Exercice guidé
  fait pratiquer avec une structure imposée
        ↓
Projet Web
  demande de décider, d'adapter et d'expliquer
        ↓
Aide-mémoire
  permet de retrouver rapidement une syntaxe
```

## 1. Page de cours

### Rôle

- expliquer le concept;
- donner le vocabulaire essentiel;
- présenter le modèle mental;
- montrer un exemple canonique;
- distinguer `À maîtriser`, `Bonne pratique` et `Pour aller plus loin`;
- donner les réflexes de diagnostic.

### À éviter

- transformer la page en procédure complète de projet;
- multiplier les variantes qui ne seront pas utilisées;
- recopier toutes les checklists de validation;
- fournir un projet presque terminé que l'étudiant pourrait réutiliser tel quel.

## 2. Exercice guidé

### Rôle

- fournir une structure et des fichiers imposés;
- faire varier une seule notion à la fois;
- faire observer le résultat dans le navigateur;
- provoquer quelques erreurs volontaires;
- demander une explication avant la correction;
- préparer directement la mission du Projet Web.

### À éviter

- réexpliquer toute la théorie;
- demander des décisions créatives importantes;
- devenir un deuxième cours complet;
- utiliser exactement le même thème, les mêmes noms et les mêmes contenus que le Projet Web.

## 3. Projet Web

### Rôle

- faire évoluer le même site pendant les rencontres 1 à 5;
- imposer un minimum suffisamment riche pour démontrer les compétences;
- demander des décisions personnelles;
- demander du contenu réel et distinct de l'exercice guidé;
- exiger que l'étudiant puisse expliquer ses choix et modifier son code.

### Structure recommandée

Chaque étape contient seulement :

1. **Mission** — ce qui doit changer aujourd'hui;
2. **Minimum attendu** — livrables concrets;
3. **Décisions à prendre** — choix du thème, du contenu ou de la présentation;
4. **Tests à effectuer** — comportements à vérifier;
5. **Compétences préparées ou disponibles**;
6. **Pour aller plus loin** — enrichissements facultatifs.

### À éviter

- recopier le gabarit complet déjà utilisé dans l'exercice;
- donner tous les textes, noms de classes et couleurs;
- permettre de remplacer le projet personnel par une copie de l'exercice;
- compter mécaniquement des propriétés sans vérifier la compréhension.

## 4. Aide-mémoire

### Rôle

- retrouver une syntaxe en quelques secondes;
- comparer deux chemins ou deux propriétés;
- rappeler une méthode de diagnostic;
- renvoyer vers la page de cours pour l'explication complète.

### Format privilégié

- tableaux courts;
- petits blocs de code;
- comparaisons;
- listes de vérification de dépannage;
- liens vers les pages canoniques.

### À éviter

- longues introductions;
- nouveaux concepts;
- exemples complets déjà présents dans le cours;
- répétition des consignes de projet.

## 5. Page d'évaluation

### Rôle

- définir les compétences et les fenêtres de validation;
- distinguer le minimum du projet et la preuve de compréhension;
- fournir une checklist par compétence;
- rappeler qu'une petite modification peut être demandée.

### Règle importante

Les minimums du Projet Web créent un support suffisamment riche pour observer les compétences. Ils ne remplacent pas la démonstration de maîtrise.

```text
Présence du code ≠ compétence automatiquement validée
Comprendre, expliquer et modifier = preuve recherchée
```

## 6. Convention pour les rappels

Lorsqu'une syntaxe a déjà été expliquée dans le cours :

- utiliser un rappel d'une ou deux lignes;
- montrer seulement la variante nécessaire;
- ajouter un lien vers la page canonique;
- ne pas répéter l'explication complète.

## 7. Revue éditoriale avant publication

Pour chaque page :

- [ ] Le rôle de la page est clair.
- [ ] Les explications complètes se trouvent dans la page canonique.
- [ ] Les rappels sont courts.
- [ ] L'exercice guidé impose une pratique, mais ne remplace pas le projet.
- [ ] Le Projet Web exige des décisions personnelles.
- [ ] Les minimums sont explicites.
- [ ] Le contenu facultatif est clairement identifié.
- [ ] Les checklists ne dupliquent pas inutilement la grille de compétence.
