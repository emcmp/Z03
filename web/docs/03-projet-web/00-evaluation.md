# Projet Web — Évaluation

Pendant les cinq premières rencontres, votre Projet Web sert à démontrer progressivement votre maîtrise de **huit compétences en HTML et CSS**.

L'ensemble de ces validations représente **30 % de la note finale du cours**.

## Votre collection de badges

Chaque compétence possède un **badge visuel**. Quand une compétence est validée, vous pouvez considérer son badge comme **acquis**.

| Badge | Compétence |
| --- | --- |
| 🗂️ | **WEB-01 — Organiser un projet Web et utiliser les chemins** |
| 🧱 | **WEB-02 — Construire une page HTML correctement structurée** |
| ✍️ | **WEB-03 — Structurer et enrichir le contenu HTML** |
| 🔗 | **WEB-04 — Relier plusieurs pages dans une navigation fonctionnelle** |
| 🔌 | **WEB-05 — Associer correctement une feuille CSS externe** |
| 🎯 | **WEB-06 — Cibler les éléments avec des sélecteurs appropriés** |
| 🎨 | **WEB-07 — Mettre en forme une interface avec CSS** |
| 📐 | **WEB-08 — Organiser l'espace et la disposition des éléments** |

:::tip Objectif : compléter votre collection
Les badges servent de repère visuel pour suivre votre progression. Le nom officiel de la compétence et son code **WEB-xx** demeurent toujours la référence pour l'évaluation.
:::

:::info Pas de grosse remise unique
Vous n'attendez pas la fin du bloc HTML/CSS pour remettre un site complet. Les compétences sont plutôt validées progressivement pendant les périodes de travail, lorsque vous êtes prêt à les démontrer.
:::

## Comment fonctionne une validation?

Chaque compétence peut avoir l'un des trois états suivants :

- **À faire** : le badge n'a pas encore été présenté;
- **À revoir** : une tentative a eu lieu, mais certains éléments doivent encore être travaillés;
- **Validée** : la maîtrise observée est suffisante et le badge est acquis.

Lorsque vous pensez être prêt :

1. vérifiez la checklist de la compétence;
2. assurez-vous que votre site fonctionne dans le navigateur;
3. demandez une validation à votre enseignant;
4. montrez la partie de votre projet concernée;
5. soyez prêt à **expliquer votre code** ou à effectuer une **petite modification** pour démontrer votre compréhension.

Une compétence indiquée **À revoir** pourra être présentée de nouveau lorsque vous aurez corrigé les éléments nécessaires et que la logistique du cours le permet.

## Calendrier des validations

Les huit compétences sont regroupées en **quatre moments de validation**. Les périodes indiquées sont des fenêtres de validation : elles ne signifient pas que toute la classe doit terminer exactement au même moment.

| Validation | Période cible | Badges / compétences | Ce qui est principalement observé |
| --- | --- | --- | --- |
| **A — Structure HTML** | **Rencontre 2** | 🗂️ WEB-01 et 🧱 WEB-02 | Organisation du projet, chemins et structure générale des pages |
| **B — Contenu et navigation** | **Rencontre 2 et début de la rencontre 3** | ✍️ WEB-03 et 🔗 WEB-04 | Contenu HTML, plusieurs pages et navigation fonctionnelle |
| **C — CSS de base** | **Rencontres 3–4** | 🔌 WEB-05 et 🎯 WEB-06 | Feuille CSS externe, chemins, sélecteurs et classes |
| **D — Mise en forme et disposition** | **Rencontres 4–5** | 🎨 WEB-07 et 📐 WEB-08 | Mise en forme, modèle en boîte, espacements et disposition simple |

:::tip Progression du groupe
Le cours continue même si une compétence est encore **À revoir**. Par exemple, le groupe peut commencer CSS pendant que certaines validations HTML restent à compléter.
:::

## Les huit compétences

Ouvrez une compétence pour voir ce qu'elle englobe et ce que vous devriez vérifier avant de demander sa validation.

<details>
<summary><strong>🗂️ WEB-01 — Organiser un projet Web et utiliser les chemins</strong></summary>

### Ce que cette compétence englobe

- organiser clairement les dossiers et les fichiers du projet;
- ranger les ressources, par exemple les images, dans un emplacement logique;
- utiliser des chemins relatifs correctement;
- comprendre les sous-dossiers et l'utilisation de `../` lorsque nécessaire.

### Avant de demander la validation

- [ ] Je peux retrouver rapidement les fichiers de mon projet.
- [ ] Mes images et mes liens utilisent des chemins relatifs qui fonctionnent.
- [ ] Je peux expliquer comment un chemin de mon projet mène au bon fichier.
- [ ] Je suis capable de corriger un chemin relatif simple qui ne fonctionne pas.

</details>

<details>
<summary><strong>🧱 WEB-02 — Construire une page HTML correctement structurée</strong></summary>

### Ce que cette compétence englobe

- utiliser la structure complète d'un document HTML;
- comprendre le rôle général de `html`, `head` et `body`;
- utiliser correctement les éléments et leurs attributs;
- imbriquer les éléments sans croiser les balises;
- garder une indentation suffisamment claire pour lire la structure.

### Avant de demander la validation

- [ ] Mes pages possèdent une structure HTML complète.
- [ ] Mes balises sont ouvertes, fermées et imbriquées correctement.
- [ ] Je peux montrer où se trouvent le `head` et le `body` et expliquer leur rôle général.
- [ ] Je peux repérer et corriger une erreur simple de structure HTML.

:::tip Bonne pratique
Valider votre HTML et garder une indentation lisible sont d'excellentes façons de repérer les erreurs avant de demander une validation.
:::

</details>

<details>
<summary><strong>✍️ WEB-03 — Structurer et enrichir le contenu HTML</strong></summary>

### Ce que cette compétence englobe

- utiliser des titres, paragraphes et listes lorsque leur rôle convient;
- ajouter des images locales correctement;
- utiliser les attributs utiles aux éléments;
- choisir des éléments HTML appropriés pour structurer le contenu.

### Avant de demander la validation

- [ ] Mon site contient du contenu structuré avec des éléments HTML appropriés.
- [ ] Mes images s'affichent correctement à partir des fichiers du projet.
- [ ] Je peux expliquer pourquoi j'ai choisi certains éléments HTML dans une partie de ma page.
- [ ] Je peux modifier ou ajouter un petit élément de contenu sans briser la structure de la page.

:::tip Bonne pratique
Les éléments comme `header`, `nav`, `main` et `footer`, ainsi qu'un texte alternatif pertinent pour les images, sont recommandés lorsqu'ils conviennent au contenu.
:::

</details>

<details>
<summary><strong>🔗 WEB-04 — Relier plusieurs pages dans une navigation fonctionnelle</strong></summary>

### Ce que cette compétence englobe

- créer plusieurs pages HTML;
- utiliser les liens avec `a` et `href`;
- construire une navigation permettant de passer d'une page à l'autre;
- utiliser correctement les chemins relatifs dans les liens.

### Avant de demander la validation

- [ ] Mon site contient plusieurs pages reliées entre elles.
- [ ] Les liens de navigation fonctionnent réellement dans le navigateur.
- [ ] Je peux expliquer le `href` d'au moins un lien de mon site.
- [ ] Je suis capable de corriger un lien qui pointe vers le mauvais fichier.

:::tip Bonne pratique
Utiliser un élément `nav` pour regrouper une navigation importante est recommandé.
:::

</details>

<details>
<summary><strong>🔌 WEB-05 — Associer correctement une feuille CSS externe</strong></summary>

### Ce que cette compétence englobe

- créer et utiliser un fichier CSS externe;
- relier une page HTML à la feuille CSS avec `link`;
- utiliser le bon chemin vers le fichier CSS;
- comprendre la syntaxe générale d'une règle CSS.

### Avant de demander la validation

- [ ] Mon CSS se trouve dans un fichier externe.
- [ ] Mes pages sont reliées correctement à cette feuille CSS.
- [ ] Je peux expliquer le chemin utilisé dans le `link`.
- [ ] Je peux reconnaître le sélecteur, la propriété et la valeur dans une règle CSS simple.

</details>

<details>
<summary><strong>🎯 WEB-06 — Cibler les éléments avec des sélecteurs appropriés</strong></summary>

### Ce que cette compétence englobe

- utiliser un sélecteur d'élément lorsque plusieurs éléments du même type doivent être ciblés;
- créer et réutiliser des classes CSS;
- choisir entre un sélecteur d'élément et une classe selon le besoin;
- comprendre à un niveau simple que plusieurs règles peuvent viser le même élément.

### Avant de demander la validation

- [ ] J'utilise des sélecteurs d'élément et des classes de façon cohérente.
- [ ] Une même classe peut être réutilisée sur plusieurs éléments lorsque cela convient.
- [ ] Je peux expliquer pourquoi j'ai utilisé une classe dans un exemple de mon site.
- [ ] Je peux modifier un sélecteur ou une classe pour cibler correctement un élément demandé.

:::tip Bonne pratique
Les identifiants `id` et la cascade CSS doivent être compris lorsqu'ils apparaissent, mais ils ne constituent pas une validation indépendante.
:::

</details>

<details>
<summary><strong>🎨 WEB-07 — Mettre en forme une interface avec CSS</strong></summary>

### Ce que cette compétence englobe

- utiliser volontairement des couleurs et des arrière-plans;
- modifier la typographie et l'alignement du texte;
- utiliser des bordures et d'autres propriétés visuelles de base;
- comprendre quelle règle CSS produit un changement visible dans la page.

### Avant de demander la validation

- [ ] Mon site possède une mise en forme CSS que je comprends.
- [ ] Je peux retrouver la règle qui modifie l'apparence d'un élément précis.
- [ ] Je peux expliquer quelques propriétés CSS utilisées dans mon site.
- [ ] Je peux modifier une propriété simple à la demande et prévoir l'effet général du changement.

:::info La validation ne compte pas les décorations
Il n'est pas nécessaire d'avoir un nombre précis de couleurs, de polices, de bordures ou de propriétés CSS. Ce qui compte est de montrer que vous savez utiliser volontairement les outils appropriés.
:::

</details>

<details>
<summary><strong>📐 WEB-08 — Organiser l'espace et la disposition des éléments</strong></summary>

### Ce que cette compétence englobe

- comprendre la relation entre le contenu, `padding`, la bordure et `margin`;
- utiliser `margin` et `padding` pour gérer les espacements;
- utiliser des dimensions simples lorsque cela est utile;
- utiliser `display: flex` et `gap` dans une disposition simple.

### Avant de demander la validation

- [ ] Je peux expliquer la différence entre `margin` et `padding`.
- [ ] Les espacements de mon site sont réglés avec des propriétés que je comprends.
- [ ] Je peux reconnaître le parent Flexbox et ses enfants directs dans un exemple de mon site.
- [ ] Je peux utiliser `display: flex` et `gap` pour résoudre un besoin simple de disposition.
- [ ] Je peux ajuster un espacement ou une disposition à la demande sans recopier une solution complète.

:::tip Bonne pratique
`justify-content` et `align-items` peuvent être utiles dans quelques cas simples. Les dispositions plus avancées ne font pas partie du noyau obligatoire.
:::

</details>

## Checklist générale — suis-je prêt à appeler mon enseignant?

Avant de demander une validation, faites ce dernier contrôle rapide :

- [ ] J'ai identifié le ou les badges que je veux faire valider.
- [ ] J'ai relu la checklist des compétences que je veux présenter.
- [ ] Mon site s'ouvre et la partie que je veux montrer fonctionne dans le navigateur.
- [ ] Je sais où se trouvent les fichiers et les lignes de code que je veux présenter.
- [ ] Je peux expliquer avec mes mots ce que fait mon code.
- [ ] Je suis prêt à répondre à une courte question sur mon travail.
- [ ] Je suis prêt à faire une petite modification ou correction si mon enseignant me le demande.

:::warning Ne demandez pas seulement « Est-ce que c'est beau? »
La validation ne porte pas sur le fait d'avoir le site le plus spectaculaire. Elle sert à vérifier que **vous comprenez ce que vous avez construit et que vous savez intervenir dans votre propre code**.
:::

## Ce qui est facultatif

Les sections identifiées **Pour aller plus loin — non évalué** dans le cours permettent d'explorer davantage, mais elles ne sont pas nécessaires pour valider les huit compétences.

Votre priorité est donc de maîtriser le noyau du cours avant d'ajouter de la complexité à votre site.
